## 垂直切片任务

### Slice 1: 子代理创建工厂（createSubagent）

**目标：** 实现从父 Agent 创建隔离子 Agent 实例的工厂函数。

**任务详情：**

1. 新建 `src/agent/subagent/create-subagent.ts`
   - 定义 `createSubagent(parentAgent: Agent, depth: number): Agent`
   - 复制父代理的 `systemPrompt`、`streamFn`、`convertToLlm`、`getApiKey`、`onPayload`、`transport`、`maxRetryDelayMs`、`toolExecution`
   - `initialState` 中 `messages` 设为空列表，`tools` 复制父代理工具列表（共享引用）
   - 新建独立的 `sessionId`（`crypto.randomUUID()`）
   - `steeringMode` 使用默认 "one-at-a-time"
   - 注意：`Agent` 构造函数内部会新建 `fileStateCache` 和 `steeringQueue`，天然隔离

2. 新建 `src/agent/subagent/create-subagent.test.ts`
   - 测试：子代理创建后 `_state.messages` 为空
   - 测试：子代理创建后 `tools` 与父代理一致
   - 测试：子代理创建后 `fileStateCache` 与父代理不是同一实例
   - 测试：子代理创建后 `listeners` 为空 Set
   - 测试：子代理创建后 `sessionId` 与父代理不同

**验收标准：**
- `createSubagent` 函数能正确创建隔离的子 Agent 实例
- 所有状态隔离测试通过

**验证步骤：**
```bash
bun test src/agent/subagent/create-subagent.test.ts
```

### Slice 2: AgentTool 基础执行

**目标：** 定义 AgentTool，实现同步执行子代理并收集结果。

**任务详情：**

1. 新建 `src/agent/tools/agent-tool.ts`
   - 定义 `inputSchema`：`prompt`（string，必需）、`description`（string，可选）
   - 定义 `outputSchema`：`result`（string，必需）
   - 实现 `execute(toolCallId, params, context)`：
     a. 从 `context` 中检查是否有父 Agent 引用（需要通过某种方式传递）
     b. 调用 `createSubagent(parentAgent, depth)`
     c. 将 `params.prompt` 作为 user message 传入子代理的 `prompt()`
     d. 等待子代理执行完成（`subagent.waitForIdle()`）
     e. 从子代理的 `_state.messages` 中提取最后一条 assistant 消息
     f. 将 assistant 消息文本内容作为 `result` 返回
   - 实现 `formatResult`：返回固定格式文本（包含子代理响应摘要）

2. 新建 `src/agent/tools/agent-tool.test.ts`
   - 测试：AgentTool schema 定义正确（name、label、description）
   - 测试：`execute` 成功创建子代理并返回结果（mock streamFn）
   - 测试：子代理无工具调用时返回 assistant 的文本响应
   - 测试：子代理执行后父代理状态不受影响

**关键设计决策：**

> **问题：如何将父 Agent 引用传递到 AgentTool.execute？**
>
> 选项 A：在 `ToolUseContext` 中新增 `parentAgent?: Agent` 字段
> 选项 B：通过闭包在创建 AgentTool 时注入父 Agent
>
> **推荐：选项 B**。`ToolUseContext` 是通用的工具执行上下文，不应包含 Agent 实例这种高层对象。AgentTool 的 `createAgentTool(parentAgent)` 工厂模式与现有 `createTodoWriteTool(store)` 一致。

**验收标准：**
- AgentTool.execute 能完整执行子代理并返回结果
- 子代理执行不污染父代理状态
- 所有基础测试通过

**验证步骤：**
```bash
bun test src/agent/tools/agent-tool.test.ts
```

### Slice 3: 安全边界（深度限制 + AbortController）

**目标：** 防止无限递归，确保 abort 信号正确传播。

**任务详情：**

1. 修改 `src/agent/types.ts`
   - 在 `ToolUseContext` 中新增 `depth?: number` 字段（当前嵌套深度，默认为 0）

2. 修改 `src/agent/tools/agent-tool.ts`
   - 在 `execute` 开头检查 `context.depth ?? 0 >= MAX_SUBAGENT_DEPTH`（`MAX_SUBAGENT_DEPTH = 3`）
   - 若超限，抛出错误：`Subagent nesting depth exceeded (max: ${MAX_SUBAGENT_DEPTH})`
   - 创建子代理时，将 `depth + 1` 传入子代理的 `ToolUseContext`
   - 子代理的 `runAgentLoop` 中，`buildToolUseContext` 需要传递 depth

3. AbortController 信号传播：
   - 子代理使用父代理的 `abortController.signal`（通过 `createSubagent` 传入共享的 signal）
   - 或：子代理新建 `AbortController`，但监听父代理 signal 的 abort 事件并联动 abort

4. 更新 `src/agent/tools/agent-tool.test.ts`
   - 新增测试：深度超限抛出错误
   - 新增测试：父代理 abort 后子代理正确终止

**验收标准：**
- 深度超过 3 时抛出错误，拒绝执行
- 父代理 abort 后子代理 loop 正确终止
- 所有安全测试通过

**验证步骤：**
```bash
bun test src/agent/tools/agent-tool.test.ts
bun test src/agent/subagent/create-subagent.test.ts
```

**验收标准：**

## 风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 子代理运行 `AgentTool` 导致无限递归 | 高 | Slice 3 的深度限制必须在 Slice 2 之后立即实现 |
| 子代理事件污染父代理 UI | 中 | Slice 1 中确保子代理 `listeners` 为空 |
| `runAgentLoop` 内部调用 `AgentTool` 时 context 传递问题 | 中 | 通过 `buildToolUseContext` 传递 depth，确保子代理能获取正确的 context |
| 子代理执行失败导致父代理 turn 失败 | 中 | 在 AgentTool.execute 中 try/catch 捕获子代理异常，返回错误结果而非抛出 |
